## 二、逐条说明

### 1. `Timeline` 增加 `x` / `y`（必须）

**问题**：自适应时间线现在可以在画布上自由拖动，但 `Timeline` schema 里没有位置字段，拖动结果保存后会被丢弃，刷新即回到默认位置。

**请求**：在 `components.schemas.Timeline` 增加两个可选数字字段。

```json
"Timeline": {
  "type": "object",
  "properties": {
    "id":   { "type": "string" },
    "name": { "type": "string" },
    "direction": { "type": "string", "enum": ["horizontal", "vertical"] },
    "points": { "type": "array", "items": { "$ref": "#/components/schemas/TimelinePoint" } },
    "x": { "type": "number", "nullable": true, "description": "面板左上角 X（画布坐标）" },
    "y": { "type": "number", "nullable": true, "description": "面板左上角 Y（画布坐标）" }
  }
}
```

**要求**
- `x` / `y` 缺省或为 `null` 时，前端会按序号自动落位（向后兼容旧数据，不会报错）。
- 位置是 8 的整数倍（前端已吸附），后端原样存即可。
- 建议同时给 `Timeline` 补一个 `"style": { "type": "object", "additionalProperties": true }`，方便以后扩展配色，非必须。

**前端已发出的报文示例**（`PUT /api/pages/{id}/canvas` 请求体片段）
```json
{
  "timelines": [
    {
      "id": "tl_1",
      "name": "案发时间线",
      "direction": "horizontal",
      "x": 120,
      "y": 96,
      "points": [
        {
          "id": "pt_1",
          "timeType": "exact",
          "time": "2026-03-14 20:00:00",
          "label": "案发",
          "startTime": null,
          "endTime": null,
          "fuzzyDate": null,
          "fuzzyPeriod": null
        }
      ]
    }
  ]
}
```

### 2. `customFields` 无损往返（必须）

**问题**：新增人物/事件/事物时会先弹窗收集资料（年龄、职业、时间、地点、类别、备注），前端写进 `CanvasObject.customFields`。双击对象时要从这里回显出原值。如果后端落库时把未知键丢掉，回显就是空的。

**schema 现状**：`CanvasObject.customFields` 已经是 `{ "type": "object", "additionalProperties": true }`，**字段本身不用改**，只需保证实现层面真的原样存取（建议 JSON 列或 TEXT 存序列化 JSON）。

**前端当前写入的键（键名固定，值都是字符串）**

| 对象类型 `type` | 写入 `customFields` 的键 |
|---|---|
| `person` | `age`、`occupation`、`description` |
| `event` | `time`、`place`、`description` |
| `thing` | `category`、`description` |

> 无填写的字段不会出现在 `customFields` 里（不是空字符串），请勿把 `customFields: {}` 变成 `null`。

**示例**
```json
{
  "id": "obj_1",
  "type": "person",
  "shape": "ellipse",
  "name": "张远山",
  "description": "案发当晚在场的第三人",
  "x": 240, "y": 160, "width": 162, "height": 72,
  "style": {},
  "customFields": {
    "age": "35",
    "occupation": "法医",
    "description": "案发当晚在场的第三人"
  }
}
```

**同时请确认**：`style`（同样是 `additionalProperties: true`）也是无损往返，前端目前写 `{}`。

---

### 3. `Annotation.content` 存真 HTML（必须）

**问题**：注解改成了真正的富文本编辑器，`content` 里会包含 `<span style="...">`、`<h4>`、`<b>`、`<u>`、`<s>` 等标签。如果列是 `VARCHAR(255)` 或做了标签白名单过滤，格式会丢。

**请求**
- 列类型用 `TEXT` / `LONGTEXT`（不要 `VARCHAR(n)`）。
- **不要做 HTML 转义或标签清洗**，按不透明字符串原样存取。
- 面板上的「注解标题」目前也存在 `content` 内部（作为开头的 `<h4 class="anno-h">`），所以一个字段就能完整往返，无需新增字段。

**示例 `content`**
```html
<h4 class="anno-h">凶器推断</h4><p>伤口角度偏左，<b>排除右手反持</b>。</p><p><span style="color: #9C5A50; background-color: #F5EFD8;">与证词第 3 条矛盾</span></p>
```

**可选优化**（非必须，做了更好）：给 `Annotation` 加一个独立的 `title` 字段，前端可切换过去，`content` 就只放正文。

```json
"title": { "type": "string", "nullable": true }
```

### 4. 成功码统一（一致性建议）

**现状**：OpenAPI 文档定义成功码为 `0`，实际接口返回 `200`。

```json
{"code":200,"message":"操作成功","data":[...]}
```

**前端已做兼容**（`code === 0 || code === 200` 都放行），所以**不改也能跑**。但建议二选一：
- 把 OpenAPI 文档的示例与说明改成 `200`（改动最小，推荐）；
- 或者后端统一改回 `0`。

**原因**：`code: 200` 与 HTTP 状态码同值，容易被误读为「网络层成功」，联调时已经踩过一次坑（前端按文档判 `0`，导致所有响应被判为失败、列表恒为空）。

### 5. `PUT /api/pages/{id}/canvas` 语义确认（关键）

**问题现象**：用户反馈「切换 page 后之前的数据会不见」。

**前端侧已定位并修复**：原实现是 800ms 防抖保存，切换 page 时旧的待保存任务会在新 page 加载后才触发，把新页数据写回、旧页改动丢失。现已改为「入队时快照 + 切页前强制落盘」，并新增按 `pageId` 的待保存队列。

**需要后端配合确认**：
1. `PUT /api/pages/{id}/canvas` 是**整体覆盖**语义（不是 merge）——前端每次提交完整的 `CanvasResponse`。
2. **事务性**：四个数组（`objects` / `relationships` / `annotations` / `timelines`）在同一事务内写入，不能部分成功部分失败。
3. **空数组要能清空**：提交 `{"objects":[],...}` 时必须把该 page 的画布清空，而不是「空数组就跳过更新」。
4. 建议返回保存后的完整 `CanvasResponse`（不是必须，前端不依赖返回值）。

**验证命令**（把 `{id}` 换成一个真实 pageId）
```bash
# 1. 读当前画布
curl -s http://localhost:8080/api/pages/{id}/canvas

# 2. 写一个对象进去
curl -s -X PUT http://localhost:8080/api/pages/{id}/canvas \
  -H "Content-Type: application/json" \
  -d '{"objects":[{"id":"obj_test","type":"person","shape":"ellipse","name":"测试","description":null,"x":80,"y":80,"width":162,"height":72,"style":{},"customFields":{"age":"30","occupation":"测试"}}],"relationships":[],"annotations":[],"timelines":[]}'

# 3. 再读，确认对象在、且 customFields.age 完好
curl -s http://localhost:8080/api/pages/{id}/canvas

# 4. 再清空，确认能清掉
curl -s -X PUT http://localhost:8080/api/pages/{id}/canvas \
  -H "Content-Type: application/json" \
  -d '{"objects":[],"relationships":[],"annotations":[],"timelines":[]}'
curl -s http://localhost:8080/api/pages/{id}/canvas
```

若第 3 步能读到、第 4 步能清空，则后端侧无问题。

### 6. 画布背景（可选，不阻塞）

前端已支持四种笔记背景：纯色（默认纯白）/ 点阵 / 方格 / 横线。因为 `CanvasResponse` 和 `PageResponse` 都没有对应字段，目前按 `pageId` 存在浏览器 localStorage，**不跟随案件、换设备就没了**。

如果希望背景跟着案件走，二选一：

**方案 A**：`CanvasResponse` 加字段
```json
"background": { "type": "string", "enum": ["plain","dot","grid","line"], "nullable": true }
```

**方案 B**：`PageResponse` 加字段（背景属于页面级设置，语义更贴）
```json
"background": { "type": "string", "enum": ["plain","dot","grid","line"], "nullable": true }
```

任选其一，前端会去掉 localStorage 兜底。
