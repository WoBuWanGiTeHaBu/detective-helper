## ⚠️ 重大坑：后端成功码是 200，不是文档写的 0

**现象**：前后端联调通了、创建 book 也成功，但刷新页面后书架看不到任何书。

**根因**：`Result<T>` 的 `code` 字段，**接口文档写的是 `0`，后端实际返回的是 `200`**（与 HTTP 状态码同值）。
实测确认：
```
GET /api/books            → {"code":200,"message":"操作成功","data":[...]}
GET /api/books/1          → {"code":200,...}
GET /api/books/1/workspace→ {"code":200,...}
```
数据一直都在库里，是前端拦截器按 `code === 0` 判定，把响应当失败丢了 `data`，
列表被赋成空数组，看起来就像「书没存进去」。

**修复**（`src/api/request.ts`）：
```ts
export const CODE_SUCCESS = 0
export const CODE_SUCCESS_HTTP = 200
export function isSuccessCode(code: number): boolean {
  return code === CODE_SUCCESS || code === CODE_SUCCESS_HTTP
}
```
两种都接受，文档改了或后端改了都不会再炸。

**同时修的两个连带问题**：
1. `bookStore.fetchBooks()` 的 catch 里原来 `books.value = []` —— **接口一抖动整屏就空**，
   加重了这次误判。改为保留上次数据 + `console.error`，不清空。
2. 项目缺 `src/env.d.ts`，导致 `import.meta.env` 报 `TS2339`。已补 `/// <reference types="vite/client" />`。

**给后端的建议**：`code` 与 HTTP 状态码混用容易误判，建议统一成 0 或明确写进文档。
